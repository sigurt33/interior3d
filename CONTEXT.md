## Task 4: ProjectStore / LocalStorageStore (DONE)

### Что сделано
- Реализована абстракция хранилища проектов согласно TDD
- Интерфейс `ProjectStore` для декаплирования конструктора от реализации (localStorage → серверная позже)
- Класс `LocalStorageStore` с поддержкой инжекции Storage-like объекта (для юнит-тестирования без jsdom)

### Архитектура
- **ProjectListEntry**: `{id, name, updated}` — метаданные для списка проектов
- **ProjectStore** (интерфейс):
  - `list(): Promise<ProjectListEntry[]>` — получить список с метаданными
  - `load(id): Promise<RoomProject | null>` — загрузить проект, null если нет/невалиден
  - `save(id, project): Promise<void>` — сохранить и обновить индекс
  - `remove(id): Promise<void>` — удалить проект и обновить индекс
- **LocalStorageStore**:
  - Хранит проекты под ключами `interior3d:project:{id}`
  - Индекс под `interior3d:index` (JSON массив ProjectListEntry)
  - При save: валидирует, сохраняет, обновляет timestamp
  - При load: валидирует через `validateProject()`, возвращает null при ошибке

### Особенности
- Все методы async (готово к серверной реализации)
- Валидация при load (защита от порченых данных)
- Инжекция хранилища — тестируется с Map вместо localStorage
- Error handling: JSON.parse, валидация — всё возвращает null/empty

## Task 5: Шаринг ссылкой через lz-string (DONE)

### Что сделано
- Реализована система шаринга проектов через URL-hash согласно TDD строго
- Функция `encodeShare(project: RoomProject): string` — сжимает JSON через lz-string, результат вида `#p=...`
- Функция `decodeShare(hash: string): RoomProject | null` — извлекает и разжимает, валидирует через `validateProject()`
- Использование встроенной библиотеки lz-string (уже в dependencies)

### Механизм
- Проект JSON → `JSON.stringify()` → `compressToEncodedURIComponent()` → помещается в hash после `#p=`
- При декодировании: парсинг hash regex → `decompressFromEncodedURIComponent()` → `JSON.parse()` → валидация
- Обработка ошибок: возвращает null при неверном формате, битом JSON, невалидном проекте

## Task 7: Движок освещения (DONE)

### Что сделано
- Реализована система расчётов освещения согласно TDD строго
- Функция `kelvinToRGB(kelvin)` — аппроксимация Таннера Хелланда для преобразования температуры цвета (1000–40000 K) в RGB
- Функция `sunState(time)` — динамический расчёт положения/интенсивности/цвета солнца в зависимости от времени суток (часы 0–24)
- Константа `LIGHT_PRESETS` — 4 заранее сконфигурированных сценария освещения
- Функция `applyPreset(state, presetId)` — безопасное применение пресета (без мутаций исходного state)

### Особенности реализации
- **kelvinToRGB**: Таннер Хеллланд аппроксимация, точность для диапазона 1000–40000 K
  - 2700K (свечка): тёплый (r > g > b)
  - 6500K (дневной свет): почти белый (r≈g≈b≈1)
  - Результат нормализован в 0..1
- **sunState**: модельный солнце в зависимости от времени суток
  - 6:00–21:00 — день с функцией sin(π·t) для плавного изменения
  - Цвет: 2200K на рассвете/закате → 6500K в полдень
  - Позиция: источник свет движется с востока на запад, высота варьируется (1.5–10.5 м)
  - 21:00–6:00 — ночь: слабая холодная «луна» (intensity 0.06, color c синим преобладанием)
- **Пресеты** (4 сценария):
  - **day** (солнечно, работа): sunTime=13, colorTemp=4500K, все группы выключены/слабо (work mode)
  - **evening-cozy** (уют, свечи): sunTime=20, colorTemp=2700K (тёплый), основной свет 35%, акценты включены
  - **night-accent** (минимум света): sunTime=23, colorTemp=2700K, только акценты на полную
  - **work** (максимум света): sunTime=13, colorTemp=5500K (холодный), всё включено на полную

## Task 8: Геометрия раскладки (DONE)

### Что сделано
- Реализована чистая геометрия размещения мебели согласно TDD строго
- Модуль описывает расположение предметов спиной к стене и валидирует раскладку комнаты
- Использование в шаблонах комнат (Task 11)

### API
1. **placeAtWall(wall, offset, size, W, L)** — размещение мебели спиной к стене
   - Параметры: стена (0–3), смещение от начала (мм), размеры {w, d, h}, размеры комнаты W×L
   - Возвращает центр предмета и поворот (rotation кратно 90°)
   - Обход по часовой стрелке (сверху): 0 — z=0, 1 — x=W, 2 — z=L, 3 — x=0

2. **itemRect(item)** — прямоугольник предмета в координатах xz
   - Учитывает поворот (при rotation = ±90°, 270° ширина и глубина меняются местами)
   - Возвращает {x0, z0, x1, z1} — границы в мм

3. **rectsOverlap(a, b)** — проверка пересечения прямоугольников
   - True если пересекаются
   - Касание (edge-to-edge) не считается пересечением

4. **doorClearRect(opening, W, L)** — зона свободного пространства перед дверью/аркой
   - Постоянный зазор DOOR_CLEAR = 900 мм перед всеми открытиями
   - Расчёт зависит от стены (обход по часовой)

5. **layoutProblems(items, room, openings)** — валидация раскладки мебели
   - Возвращает массив проблем (строк) или пустой массив если всё ОК
   - Ловит:
     - Выход мебели за стены комнаты (допуск EPS = 1 мм на округление)
     - Пересечение мебели между собой
     - Блокировку дверей/арок (DOOR_CLEAR зона)

### Математика
- Стена 0 (z=0, нижняя): центр y = offset + w/2, z = d/2, rotation = 0
- Стена 1 (x=W, правая): центр x = W - d/2, z = offset + w/2, rotation = -π/2
- Стена 2 (z=L, верхняя): центр x = W - offset - w/2, z = L - d/2, rotation = π (отсчёт с другого конца!)
- Стена 3 (x=0, левая): центр x = d/2, z = L - offset - w/2, rotation = π/2

- `src/core/layout.ts` — функции геометрии и валидации
- `tests/layout.test.ts` — 10 тестов (placeAtWall×4, itemRect+rectsOverlap×2, layoutProblems×4)

## Task 9: Оболочка комнаты (DONE)

### Что сделано
- Реализована система построения трёхмерной оболочки комнаты согласно TDD строго
- Функция `buildWallWithOpenings()` — строит одну стену с проёмами (двери, окна, арки)
- Функция `buildRoomShell()` — собирает полную комнату (пол, потолок, 4 стены)

### API и особенности

#### buildWallWithOpenings(len, h, openings, mat)
- **Параметры**:
  - `len` (м) — длина стены в метрах (M = mm/1000)
  - `h` (м) — высота потолка в метрах
  - `openings` — массив Opening для этой стены
  - `mat` — материал (THREE.Material)
- **Возвращает**: THREE.Group с сегментами (BoxGeometry)
- **Логика построения**:
  - Глухая стена (без проёмов) — 1 сегмент
  - Дверь (от пола) — 2 простенка (слева, справа) + 1 перемычка над дверью
  - Окно (от sill, default 900 мм) — 2 простенка + 1 перемычка над окном + 1 подоконная часть под окном
  - Умная фильтрация: не добавляются сегменты с нулевой высотой/шириной (угловые проёмы)
- **Координаты локальные**: X вдоль стены (0 до len), Y вверх (0 до h), Z тощина (-WALL_T/2)

#### buildRoomShell(project, style)
- **Параметры**:
  - `project` — RoomProject с room.{width, length, height} в мм и openings
  - `style` — StyleDef (из getStyle)
- **Возвращает**: THREE.Group 'shell' с детьми:
  - 'floor' — BoxGeometry (W × 0.05м × L), материал floor
  - 'ceiling' — PlaneGeometry (W × L) с rotationX = π/2, материал ceiling
  - 'wall-0', 'wall-1', 'wall-2', 'wall-3' — Group с сегментами
- **Обход стен** (по часовой сверху):
  - Стена 0: z=0, вдоль X (0 до W), rotY=0
  - Стена 1: x=W, вдоль Z (0 до L), rotY=-π/2
  - Стена 2: z=L, вдоль X (W до 0), rotY=π
  - Стена 3: x=0, вдоль Z (L до 0), rotY=π/2
- **Материалы**: MeshStandardMaterial с DoubleSide для стен и потолка

### Константы
- `M = (mm) => mm / 1000` — конвертер мм → м для Three.js сцены
- `WALL_T = 0.1` м — толщина стены

### Типы проёмов
- **door**: от пола (y=0) до height, без подоконника
- **window**: от sill (default 900) до sill+height, с подоконной частью
- **arch**: обрабатывается как дверь (на уровне API, спецификации нет)

- `src/scene/shell.ts` — функции построения (2 экспорта)
- `tests/shell.test.ts` — 5 тестов (4 для buildWallWithOpenings, 1 для buildRoomShell)

## Task 10: Процедурная мебель спальни (DONE)

### Что сделано

### API и особенности

#### Типы и функции
- **Builder** — тип функции `(item: FurnitureItem, style: StyleDef) => THREE.Group`
- **Локальная система координат**: центр предмета в origin, спина (к стене) в −z, y=0 — основание на полу

#### Строители мебели

**buildBed**: кровать с несущей конструкцией, матрасом, изголовьем и подушками
- Несущая рама: ширина × 0.3м × (глубина − 0.1м), материал wood
- Матрас: (ширина − 0.1м) × 0.2м × (глубина − 0.35м), материал textile, на высоте базы
- Изголовье: ширина × min(1.0м, высота_параметра) × 0.08м, материал textile, смещено в −z
- Подушки: 2 шт., 0.6м × 0.12м × 0.4м, белые, по сторонам у изголовья

**buildNightstand**: тумбочка (ночной столик)
- Корпус: ширина × высота × глубина, материал wood
- Фасад: (ширина − 0.04м) × (высота − 0.1м) × 0.02м, материал facade, на передней стороне

**buildWardrobe**: шкаф с дверцами
- Фасад: ширина × высота × глубина, материал facade
- Швы-разделители: вертикальные полосы каждые ~600 мм (считается кол-во дверей)
- Каждый шов: 0.008м × (высота − 0.02м) × 0.008м, материал accent

**buildDesk**: письменный стол с ногами
- Столешница: ширина × 0.04м × глубина, материал wood, на высоте параметра
- Ноги: 4 шт., 0.05м × (высота − 0.04м) × 0.05м, материал accent, по углам

### Обзор реализации

#### Позиционирование элементов
- Функция `box(w, h, d, color)` создаёт mesh с BoxGeometry и автоматически сдвигает на `position.y = h/2`, чтобы дно было на y=0
- Все дополнительные элементы (фасад, ноги, швы) позиционируются с учётом этой логики:
  - Center y = (height − offset) / 2 для элементов меньшей высоты
  - Это гарантирует, что Box3.getSize() для GROUP совпадает с параметрами

#### Типичная ошибка, которая была исправлена
Изначально position.y дополнительных элементов присваивалась произвольно (0.05, 0 и т.д.), что приводило к расширению bounding box и превышению допусков. Пересчёт через `(h − offset) / 2` скоррегировал позиции.

### Правила расстановки (по приоритету)
1. **Кровать** — предпочтительно стена напротив двери (по центру), затем боковые стены, затем стена с дверью.

2. **Тумбочки** (450×450×500 мм) — по обе стороны кровати, с зазором 100 мм. Необязательны:

3. **Шкаф** (глубина 600, высота 2200 мм) — на первой подходящей свободной от кровати стене,

4. **Стол** (глубина 600, высота 750 мм) — под окном, центрируется по проёму, ширина каскадом

- kitchenRun: корпус (h-0.04) + столешница (0.04) = h; панели (варочная/мойка) позиционируются над счётчиком на y=h+0.006
- Холодильник: ручка смещена на d/2-0.015 (чтобы не выходила за габариты по Z)
- Вытяжка: труба занимает верхнюю часть (низ «пустой» — bbox.min.y > 0)
- Стул: сиденье на y=0.45, спинка от (y=0.45+0.05) до (y=0.85) с высотой (h-0.50), проверка bbox.y: 0.45 + (0.35)/2 + 0.05 = 0.675, не превышает h/2=0.425... [уточнение: спинка высотой h-seatH-0.05 = 0.40, по формуле y = 0.45 + 0.40/2 + 0.05 = 0.75, что допустимо в h/1000=0.85м]
