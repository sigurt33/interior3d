# Спека: веб-конструктор интерьеров (MVP)

Дата: 2026-08-11
Статус: утверждена пользователем (дизайн-сессия в Claude Code)

## 1. Суть продукта

Веб-сервис для быстрого создания дизайна комнаты: пользователь вводит размеры,
отмечает окна и двери, выбирает стиль — получает интерактивную 3D-комнату
с расставленной мебелью и полноценным управлением освещением. Работает
в браузере на телефоне и ПК, без установки и без регистрации.

Прототип-предшественник: проект «дом 6 комнат» (`ClaudeC/kuhnya`,
https://sigurt33.github.io/kuhnya-3d/) — тот же подход (Three.js, процедурная
мебель, процедурные материалы), но собранный вручную под один конкретный дом.
Сервис — обобщение этого опыта в параметрические шаблоны.

## 2. Ключевые решения (из брейншторма)

| Вопрос | Решение |
|---|---|
| Аудитория | Обычные люди (ремонт себе) + строители/застройщики |
| Сценарии | MVP: размеры → 3D-конструктор. Этап B: фото комнаты → AI-рестайл |
| Формат | Веб (SPA). Позже возможна Android-обёртка (Capacitor/WebView) |
| Движок дизайна | Конструктор + параметрические шаблоны. AI — позже, точечно |
| Освещение | Время суток, группы светильников, цветовая температура, пресеты |
| Монетизация | Не прорабатывается на этапе MVP |
| Архитектура | Вариант A: чистый клиент без сервера, с заделом на B (лёгкий бэкенд) |

## 3. Архитектура

Одностраничное приложение без сервера. Статический хостинг — GitHub Pages.

Центральный принцип: **вся комната описывается одним JSON-документом
(`RoomProject`), рендер — чистая функция от него.** Изменение любого параметра
→ перестройка/обновление сцены. Никакого состояния, живущего только в сцене.

Задел на этап B:
- Доступ к хранилищу только через интерфейс `ProjectStore`
  (MVP-реализация — localStorage; серверная реализация подключается без
  изменений в конструкторе).
- Фото-рестайл — отдельный модуль-клиент внешнего API; в MVP присутствует
  как кнопка-заглушка «Скоро» в UI, чтобы зарезервировать место в потоке.
- Формат шаринг-ссылки (сериализованный `RoomProject`) — тот же формат,
  который позже поедет на бэкенд.

## 4. Модель данных

```ts
RoomProject {
  meta: { name: string, created: string, version: 1 }
  room: { type: 'kitchen'|'bathroom'|'bedroom'|'kids',
          width: number, length: number, height: number }   // мм
  openings: [ { kind: 'door'|'window'|'arch', wall: 0|1|2|3,
                offset: number, width: number, height: number,
                sill?: number } ]
  style: { palette: string, floorMaterial: string,
           wallMaterial: string, accentMaterial: string }
  furniture: [ { id: string, type: string,
                 wall?: number, slot?: number,               // слотовая привязка
                 position?: {x,z}, rotation: number,
                 size: {w,d,h}, options: object } ]
  lighting: { preset: string|null, sunTime: number,          // 0..24
              colorTemp: number,                             // 2700..6500 K
              groups: [ { id: string, on: boolean, brightness: number } ] }
}
```

- Схема версионируется с первого дня (`version: 1`); при изменении схемы
  пишется миграция, старые сохранённые проекты обязаны открываться.
- Валидация схемы при загрузке (из localStorage или из ссылки); невалидный
  документ не роняет приложение, а показывает понятную ошибку.

## 5. Шаблоны комнат

Стартовый набор — 4 типа: **кухня, ванная, спальня, детская** (знания
переносятся из part3.html проекта-предшественника).

Шаблон — не готовая сцена, а набор правил расстановки:
- вход: размеры комнаты + проёмы;
- выход: список мебели со слотовой привязкой к стенам;
- пример правила (кухня): рабочая линия вдоль стены с окном
  (холодильник → плита → мойка → посудомойка), обеденная зона у окна;
- шаблон обязан давать валидную расстановку для любых разумных размеров
  (мебель не пересекается, не перекрывает проёмы, не вылезает за стены);
  при невозможности — сокращает состав мебели, а не ломается.

После автогенерации пользователь может двигать (по слотам), заменять
и удалять предметы.

## 6. Стили и материалы

3–4 стиля на старт:
1. **Бежевый минимализм** — перенос отработанного стиля (бежевые фасады
   с чёрным пазом, дерево, чёрные акценты);
2. Светлая классика;
3. Тёмный контраст;
4. Скандинавский.

Стиль = палитра + материалы (пол, стены, фасады, столешницы) + правила
акцентов. Материалы процедурные (цвета, простые паттерны) — без тяжёлых
фототекстур, чтобы быстро грузилось на телефоне.

## 7. Мебель

Процедурная, из примитивов Three.js (боксы, цилиндры) — подход, проверенный
на проекте-предшественнике. Переиспользуемые строители:
`buildBed(size, style)`, `buildSofa(...)`, `buildKitchenLine(...)`,
`buildWardrobe(...)` и т.д. Каждый строитель:
- параметрический (любые разумные размеры);
- принимает стиль и красится сам;
- возвращает `THREE.Group` с метаданными для выделения/редактирования.

Стартовый набор — предметы, уже существующие в part3.html, переписанные
в функции.

## 8. Освещение (ключевая фишка)

Четыре механизма, все управляют одним состоянием `lighting`:
1. **Время суток** — слайдер 0–24: положение, интенсивность и цвет солнца
   из окон (утро тёплое низкое → полдень белый → закат оранжевый →
   ночь синяя «луна»).
2. **Группы светильников** — определяются шаблоном (потолочные, подвесы,
   подсветка): у каждой вкл/выкл + яркость.
3. **Цветовая температура ламп** — слайдер 2700–6500 K → цвет источников.
4. **Пресеты** — 4 кнопки: «День», «Вечер уютный», «Ночь с подсветкой»,
   «Рабочий свет». Пресет выставляет все параметры выше; ручное изменение
   любого слайдера снимает отметку пресета (state становится кастомным).

Пресеты — вход для массового пользователя; слайдеры — для дотошного.

## 9. Поток пользователя (UI)

Мобильный в первую очередь. Мастер из 4 шагов:
1. Тип комнаты (4 карточки);
2. Размеры (ширина/длина/высота) + проёмы (стена, отступ, ширина);
3. Стиль (карточки с превью);
4. Готовая 3D-комната.

Режим просмотра:
- кнопки ракурсов (общий, от входа, ключевые зоны, сверху — как в доме);
- панель освещения (пресеты + разворачиваемые слайдеры);
- редактирование: тап по предмету → заменить / подвинуть (по слотам вдоль
  стен) / убрать. Свободного drag-and-drop в 3D нет — сознательно:
  слоты проще и надёжнее на телефоне;
- кнопка «Поделиться» (ссылка), кнопка «Фото-рестайл» (заглушка «Скоро»).

«Мои комнаты» — список сохранённых проектов (localStorage).

## 10. Сохранение и шаринг

- Автосохранение текущего проекта + список проектов в localStorage
  через `ProjectStore`.
- Шаринг: полный `RoomProject` сжимается lz-string → в hash-часть URL.
  Получатель открывает ссылку и видит ту же комнату; сервера нет.
- Ограничение: если сериализованный проект превышает безопасную длину URL
  (~30 КБ в hash), показываем предупреждение (на практике проекты — единицы КБ).

## 11. Технологии и структура кода

- Vite + TypeScript + Three.js (актуальный модульный, r160+).
- Папка проекта: `C:\Users\User\ClaudeC\interior3d`, git с первого коммита,
  деплой — GitHub Pages (отработанный путь).
- Структура:
  - `src/core/` — модель `RoomProject`, валидация, `ProjectStore`, шаринг;
  - `src/templates/` — шаблоны комнат (по файлу на тип);
  - `src/furniture/` — процедурные строители мебели;
  - `src/lighting/` — солнце, группы, температура, пресеты;
  - `src/ui/` — мастер, панели, ракурсы;
  - `src/scene/` — сборка Three.js-сцены из `RoomProject`.
- Файлы маленькие, по одной ответственности (антипример — монолитный
  part3.html, который стало тяжело править).

## 12. Проверка качества

- Юнит-тесты шаблонов: для сетки размеров каждая комната даёт валидную
  расстановку (нет пересечений, нет выхода за стены, проёмы свободны).
- Валидация JSON-схемы: загрузка битого/чужого документа не роняет
  приложение.
- Скриншот-тесты (Playwright, скрипт по образцу отработанного shots.mjs):
  эталонные кадры «каждая комната × каждый стиль × пресет света»,
  сравнение при изменениях.
- Ручная проверка на телефоне (главная платформа аудитории).

## 13. Вне рамок MVP (сознательно)

- Фото-рестайл (этап B: лёгкий бэкенд + API картиночной нейросети);
- аккаунты и синхронизация между устройствами;
- распознавание размеров с фото чертежа;
- непрямоугольные комнаты и свободная планировка стен;
- каталог реальной мебели с ценами/ссылками;
- экспорт в PDF/изображения высокого разрешения;
- монетизация.

## 14. Критерии успеха MVP

- Пользователь на телефоне за ≤3 минуты от открытия сайта доходит до
  своей 3D-комнаты с реальными размерами.
- Освещение управляется всеми четырьмя механизмами и заметно меняет
  восприятие комнаты.
- Ссылка-шаринг открывается на другом устройстве и показывает ту же комнату.
- Все 4 типа комнат дают валидную расстановку на разумном диапазоне
  размеров (примерно от 2×2 до 10×15 м).
